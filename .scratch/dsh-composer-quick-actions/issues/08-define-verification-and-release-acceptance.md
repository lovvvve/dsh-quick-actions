# 定义验证与发布验收标准

Type: grilling
Mode: HITL
Status: resolved
Blocked by: 07

## Question（问题）

哪些证据能够证明持久化快捷动作插件已经完整实现并可安全发布？请定义单元测试和集成测试契约、跨重启的持久化覆盖范围、预置升级场景、消息编辑器交互与无障碍检查、窄布局检查、停止或更新时的生命周期清理、失败路径测试、构建和软件包验证、安装文档，以及在现有 DSH Web GUI 中执行的确切手动验收流程。

## Answer（答案）

### 发布硬门槛与证据

最终候选提交上的类型检查、lint、单元测试、集成测试、构建、pack、安装 smoke 和人工验收必须全部以新鲜运行通过；不允许跳过、只跑子集或引用历史结果。任何内容丢失、重复发送、持久化损坏、消息编辑器崩溃或其他高严重度已知缺陷都阻止发布。仅地图明确列入范围外且已经写入 README 的限制可以保留。

验证证据统一写入 `.scratch/dsh-composer-quick-actions/verification/release-evidence.md`，记录精确命令、时间、版本、通过与失败数量及退出码；浏览器检查链接截图，安装/重启记录一次性 profile。不得记录凭据、授权头、真实用户数据或真实对话内容。没有这份证据和用户最终明确的“生产验收通过”，不得完成地图目标。

首版自动化使用当前 Node 版本和 Playwright Chromium；人工验证使用现有 `http://127.0.0.1:3080` DSH GUI，并覆盖桌面、约 768px 和约 360px 三种宽度。当前操作系统执行安装与卸载 smoke。首版不宣称已覆盖其他浏览器引擎或其他操作系统。

覆盖门槛以行为矩阵而非统一行覆盖率百分比衡量。共享领域模块的每条不变量和迁移分支必须有直接测试；每个 bug 修复必须先加入能复现原症状的回归测试。自动化禁止真实 LLM 与外部网络；发送、queue、失败恢复使用受控 fake Session/Remote。人工测试使用一次性会话，除非用户主动同意，否则不触发真实模型调用。

### 数量与性能边界

内置与 Host 配置组成的预置目录最多 50 个动作；正常状态下，预置与自定义动作合计最多 50 个，隐藏和停用项也计数。达到上限后禁止新增和克隆，但允许编辑、删除、隐藏、停用和排序。超限配置或正常写入明确拒绝，不静默截断。

若插件升级新增预置，使原本合法的既有状态被动超过 50，系统不得删除、隐藏或拒绝加载任何已有动作。全部动作继续可见和可管理，管理界面显示超限警告，并禁止新增或克隆，直到总数恢复到 50 以内。自动化规模场景覆盖 0、1、6、25、50 个动作，以及由升级形成的 53 个既有动作。不得出现无限重渲染、明显卡顿或每个动作一次 Remote 调用；Client 每个连接 generation 最多读取一次目录。

### 核心接口与领域单元测试

`inputActions.insertText` 必须覆盖范围选区替换、光标插入、无选区末尾回退、引用占位符清理、空输入无操作、独立撤销边界、未替换富内容保留和同步 `void` 契约。

共享领域模型必须覆盖稳定 ID、插入/发送判别联合、默认值、标签/文本/emoji/数量限制、发送动作禁止斜杠命令、克隆独立性、隐藏/停用和三个布局值。排序测试覆盖重复引用、失效自定义引用、未知预置保留及缺失已知动作追加。升级测试覆盖新增、文案变化、删除、重新加入以及行为签名改变时必须使用新 ID。迁移测试覆盖 V1 向后读取、幂等规范重写和 revision 冲突。目录 revision 对同一规范目录必须稳定，并在任何可见目录变化后改变。

### Host 与 Client 集成测试

验证 `settings` 缺失时 Host 等待、出现后注册、卸载后解除 namespace 但保留文件 section；验证内置与 Host 配置预置合并、重复 ID、超限目录和无效配置失败。`describeCatalog` 只能返回合法 JSON 目录，不能暴露 Settings CRUD。

Settings 写入必须先持久化再提交，重启后恢复用户动作、顺序、隐藏状态和布局。Client 每个连接 generation 至多读取一次目录，不按 Session 或动作重复 RPC。覆盖首次目录失败、重连、Settings 只读、短暂断线、最后确认快照、写入拒绝与 revision 冲突恢复。Host/Client fiber dispose 后不得残留监听器、Remote、namespace、样式或重复订阅。

### UI 与动作执行测试

A/B/C 三种布局选择必须跨重启保存；A/B 与输入框左右边界误差不超过 1 CSS px。桌面、768px、360px 下验证溢出、搜索、管理、面板和焦点。视觉截图基线覆盖三种布局与桌面/窄布局；截图差异用于审查，但跨平台字体的轻微像素差异不单独阻断，DOM 结构、边界、状态和焦点断言才是自动硬门槛。

覆盖预置排序/隐藏/克隆和自定义 CRUD/启停。插入测试验证选区、光标、焦点、鼠标/键盘一致性、重复插入和逐次撤销。发送测试验证任何文本（包括空白）、图片或引用都会禁用动作；确认取消、最终状态重验、动作删除、会话切换、按会话单飞和模型运行期间原生 queue 均符合契约。提交前异常必须保留文本，官方失败恢复不得产生重复错误。缺少 `insertText` 的旧 DSH 版本只禁用插入动作，发送与管理保持可用。

键盘遍历、Enter/Space、Esc、焦点返回、可访问名称、适用的 WCAG AA 对比度和每个 Slot 的局部错误边界都是硬门槛。成功动作不产生额外 toast。

### 构建、安装、卸载与生命周期

验证 Host ESM、Client lazy-CJS、sourcemap、externals 和假的 ModuleLoader 契约。两个包必须成功 `pack`；将 bundle 安装进一次性 web profile 后必须在重启时激活。浏览器验证只使用现有 DSH URL，不得启动替代服务器冒充当前 GUI；验证开发 HMR 前必须确认同一 DSH checkout 的 Client build watcher 正在运行。

stop、update 和 unload 后不得残留或重复 Slot、样式、监听器、Remote 或 Settings binding。卸载 bundle 并重启后 UI 与运行时注册消失，但 Settings 用户 section 保留；重新安装后恢复全部用户配置。README 的安装、配置、升级、降级、卸载和手工彻底清理步骤必须逐条实际执行成功。

### 最终人工验收

自动化全部通过后，用户在一次性测试会话中完成：

1. 安装最终 tarball，重启并刷新现有 DSH GUI。
2. 创建插入与发送动作，验证编辑、排序、停用、隐藏和克隆。
3. 分别检查 A/B/C、输入框等宽与三种视口。
4. 验证选区插入、焦点、撤销和连续插入。
5. 验证空草稿发送、占用草稿禁用、确认取消与确认发送。
6. 刷新页面并重启 DSH，确认全部设置恢复。
7. 卸载并重启，确认 UI 消失；重新安装后确认配置恢复。
8. 检查错误信息、键盘流程和无障碍名称。
9. 明确回复“生产验收通过”。

原型阶段的确认不能替代最终生产实现验收。

## Comments（评论）

### 2026-09-05 — 发布验收改为能力双通道

[将 insertText 补丁集成到 DSH 官方发布](./19-upstream-insert-text-and-record-release.md)替代本答案中“缺少 `insertText` 时只禁用插入动作”、“必须先有正式最低版本”，以及“人工验证/浏览器验证只使用现有 DSH URL”的两处限定：现有 `http://127.0.0.1:3080` 只用于官方能力缺失通道；隔离 patched 能力通道允许受管独立 URL，但仍不得把它冒充当前 GUI。最终候选仍须满足本答案的全部新鲜证据门槛，但分为两个必过通道：当前官方 DSH 验证兼容性抑制、管理/持久化与发送；已验证核心补丁环境验证完整插入行为。能力缺失时插入动作从 Composer 列表省略，在管理界面继续可配置并计入所有数量场景；该通道还必须证明发送动作在最终空草稿重验后使用公共 `setDraft` + `submit` 且不调用缺失的 `insertText`。能力通道则从官方基线创建隔离源码检出并应用已验证补丁，通过受管后台任务提供明确的独立 GUI URL，在真实插件与编辑器联动中验证插入行为及发送使用公共 `insertText` + `submit`；它不得修改已安装 `node_modules` 或冒充当前 GUI。两者的写入后失败都必须保留草稿。相同 Settings 快照还须直接覆盖能力 false→true→false 时兼容性抑制插入动作无写入地省略、按原顺序恢复和再次省略，管理数据、计数与顺序不得变化。兼容矩阵不得虚构最低正式 DSH 版本；最终人工验收清单中的插入步骤在该隔离能力通道执行。
