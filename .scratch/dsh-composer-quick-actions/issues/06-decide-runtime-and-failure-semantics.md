# 确定运行时与失败语义

Type: grilling
Mode: HITL
Status: resolved
Blocked by: 02, 05, 09

## Question（问题）

在消息编辑器的每种状态下，插入动作和发送动作必须呈现哪些可观察行为？请确定选区替换和光标位置、空白字符处理、与现有草稿的交互、取消发送确认时的处理、快速重复点击时的处理、消息编辑器处于禁用或流式输出状态时的处理、发送失败、持久化失败、用户反馈，以及直接发送失败后是否恢复任何草稿状态。

## Answer（答案）

### 插入动作

插入动作原样传递已保存文本，不自动添加空格或换行。它通过公共 `inputActions.insertText(text)` 替换当前范围选区，或在当前光标处插入；没有有效选区时追加到文档末尾。完成后消息编辑器保持或恢复焦点，光标位于插入文本之后，鼠标与键盘激活必须一致。

每次有效激活都插入一次并形成独立撤销单元；允许用户有意连续插入。只有在原生编辑器可编辑时才可执行，核心接口缺失或原生 guard 锁定时保持可见但禁用，并说明原因。

### 发送动作

发送动作仅在草稿完全未占用时可用。任何文本（包括纯空白）、图片附件或富引用都视为已有草稿；动作保持可见但禁用，并提示用户先处理当前草稿。发送动作的文本若首个非空白字符为 `/`，则配置无效且不得执行；命令文本只能通过插入动作让用户检查后手动提交。

需要确认时，弹窗展示动作标签和完整待发送文本，确认前不改变草稿。取消、按 Esc、点击遮罩、动作在等待期间被删除，或组件卸载都没有副作用。用户最终确认时必须重新读取动作定义、当前会话、草稿占用和原生 guard；任一条件变化就取消发送且不修改草稿，并提示“状态已变化，请重试”。无需确认的动作也在执行前完成同样验证。

验证通过后，动作按会话进入单飞状态，调用 `insertText(text)` 后立即沿官方 `inputActions.submit()` queue 路径提交。原生消息编辑器允许排队时，模型流式输出期间也可以发送；disabled、blocked、removed、adjudicating 或 submitting 状态下不可执行。同一会话从首次激活直到取消确认或官方提交阶段结束，不接受第二次发送动作；其他会话不受影响。

若动作文本已插入，但 `submit()` 前后出现同步异常或状态机未接收提交，插件不得删除或自动重提文本；它结束单飞，将文本留在草稿中并提示“未发送，文本已保留”。消息已进入官方提交路径后若发送失败，则完全依赖 DSH 原生错误反馈和失败草稿恢复；插件不自动重试、不复制草稿，也不显示重复错误。状态恢复后，用户可编辑或再次发送。

### 可见性、会话与反馈

用户隐藏的预置快捷动作和停用的自定义快捷动作不出现在消息编辑器，只在管理界面中可恢复。因草稿、原生状态或 DSH 版本而暂不可用的动作仍显示为禁用，并提供具体原因。no-session、hero 和 takeover 状态本就不在首版范围内，因此不渲染快捷动作。

会话切换、常驻消息编辑器卸载或 Slot 被替换时，尚未进入官方提交状态机的确认和待执行状态立即取消；已经提交的发送继续由原会话完成，绝不迁移到新会话。成功插入后的可见文本与焦点、发送后的本地消息回显就是成功反馈，不额外显示 toast；只有错误、状态变化和不可用原因需要额外提示。

### Settings 失败与断线

新增、编辑、排序、隐藏、启停或删除动作时，界面等待 Host Settings 写入成功后才提交新状态。失败时保留编辑内容或恢复原顺序，保持管理界面打开，并显示可重试的明确错误；修订冲突会刷新最新状态并要求用户重新确认，不保留另一套可编辑的离线真相。

应用首次启动即无法读取 Settings 时，只显示软件包内置及 Host 配置预置，管理界面为只读并提示存储不可用。成功加载后发生短暂断线时，继续显示并允许执行最后一次 Host 确认的用户动作快照，但管理界面保持只读；连接恢复后重新同步。

## Comments（评论）

### 2026-09-05 — 缺少核心能力时的呈现与发送装载已被后续范围决策替代

[将 insertText 补丁集成到 DSH 官方发布](./19-upstream-insert-text-and-record-release.md)替代本答案中的两处兼容语义。第一，因 DSH 缺少公共插入能力而不能执行的插入动作现在是兼容性抑制插入动作，从 Composer 动作列表省略，但仍在管理界面保留、允许配置并计入上限；因草稿占用、原生 guard 或临时消息编辑器状态而不能执行的动作仍是暂不可用快捷动作，继续显示为禁用并说明原因。第二，发送动作在最终重验草稿未占用后装载文本：公共 `insertText(text)` 存在时使用它，缺失时仅为本次发送使用公共 `setDraft(text)`，随后调用公共 `submit()`。`setDraft` 不得用于插入动作；写入后若提交同步异常或未进入官方状态机，文本仍留在草稿中且不自动重试。其余运行时与失败语义不变。
